# Render와 Reconciliation

## 정의


<toggle>
<b>Render 단계는 어떤 단계인가요? </b>

- Render는 UI를 계산하는 단계입니다. 이 과정에서 컴포넌트를 실행하고 리콘실레이션 재조정과정을 통해 이전 렌더링 결과와 다음 렌더링 결과를 비교하여 필요한 변경사항을 판단합니다. 이후 실제 DOM에 이 변경사항을 반영하는 단계는 커밋단계에서 진행합니다.
</toggle>

<toggle>
<b>React가 이전 UI와 새로운 UI를 비교할 때, 무엇을 기준으로 기존 컴포넌트를 유지하거나 새로 생성할지 판단할까?</b>

- 리액트는 key와 요소의 타입을 기준으로 dom 요소를 재사용할지 판단합니다. 같은 타입과 같은 위치의 요소일 경우, dom 요소를 재사용하며 className이나 텍스트 등만 변경합니다. 하지만 다른 타입일 경우 그러니까 div에서 span으로 변경되었음을 계산한였을때는 dom 요소 위치의 하위트리를 제거하고 새로운 요소를 생성합니다.
- <b>판단 기준 : type과 key</b>
</toggle>

<toggle>
<b>(React 05)목록에서 항목이 삽입되거나 순서가 바뀔 때 key는 React가 이전 항목과 새 항목을 연결하는 데 어떤 역할을 하나요?</b>

key는 목록에서 각 항목을 식별하는 기준으로 사용됩니다. 항목이 삽입되거나 순서가 변경되어도, 같은 부모 아래 동일한 key를 사용할 경우, 이전 렌더링 결과에서 컴포넌트를 대응시킬수있습니다. 기존 컴포넌트의 local state를 보존할수있습니다.
</toggle>

<toggle>
<b>(React 06)가정: 목록 중간에 항목을 삽입하면서 index를 key로 쓰면 각 행의 local state가 어떤 항목에 남을 수 있나요?</b>

로컬 스테이트는 기존에 위치하던 항목에 그대로 남습니다. 예를 들어 index 2에 바나나가 있었고 상태를 true로 갖고 있었으나, 2에 사과가 들어와 기존 2에 바나나가 3으로 밀린 상태입니다. 그렇다면 인덱스 2는 사과가 존재하지만 그대로 상태는 true로 갖습니다. 왜냐하면 리액트에서 상태는 같은 트리내의 위치와 동일성을 기준으로 관리하고 연결하기 때문입니다. 같은 key와 같은 위치 안에 컴포넌트가 존재하기 때문에 상태는 연결되어있어, 상태가 바나나가 아닌 사과에 연결됩니다.
</toggle>

<toggle>
<b>state props가 변경되면 컴포넌트는 리렌더링되지 않을까?</b>

컴포넌트는 부모 컴포넌트가 리렌더링 되면 자식 컴포넌트도 리렌더링 되기 때문에 state나 props가 변경되지 않아도 리렌더링 될 수 있습니다.
</toggle>

<toggle>
<b>(꼬리질문)그렇다면 리렌더링 계산을 줄이기위해 컴포넌트분리도 중요할까?</b>

<p>
실제로 state를 어디에서 관리하느냐가 관건이다. 부모에서 상태를 관리하면, 상태변경이 발생되었을때 부모 컴포넌트가 리렌더링 되면서 자식 컴포넌트도 함께 리렌더링에 참여되기 때문이다.하지만, 자식컴포넌트에서 상태가 변경되었을때는 부모 컴포넌트는 리렌더링에 참여되지 않는다. 때문에 업데이트 영향으로 발생하는 UI 재계산을 상태 범위를 통해 줄일수있다. 
</p>
</toggle>

> <b>특징 정리</b>

- 재조정단계에서 이전 렌더링 결과와 다음 렌더링 결과를 비교할때 <b>key와 요소의 타입</b>을 기준으로 컴포넌트를 재사용할지 판단한다.
  - 같은 위치 + 같은 타입 + 같은 key : 동일성 유지 → 상태, 요소 보존
  - 같은 위치에서 타입 변경
    - 컴포넌트의 타입이 변경될때, 컴포넌트가 리마운트 되기 때문에 상태 초기화.
    - dom 요소의 타입이 변경될때, 상위 컴포넌트의 상태가 보존될 수 있다.
  - 같은 위치에서 key가 변경될때, 해당 컴포넌트의 상태는 초기화된다.
    - 리액트에서 <b>상태</b>는 렌더트리의 컴포넌트 위치와 동일성을 기준으로 관리된다.
    - key가 변경되면, 컴포넌트는 리마운트되고 이전 컴포넌트와 다음 컴포넌트는 서로 다른 컴포넌트로 판단하기 때문에 컴포넌트의 동일성이 깨진다.
  - 위치가 변경될때
    <ul>
    <li>
    컴포넌트가 리마운트되기 때문에 해당 컴포넌트가 참조하던 상태가 초기화 된다. 
    </li>
    <li>
    하지만, 리스트 등과 같이 안정적인 key를 사용할 경우 컴포넌트 동일성 보존 가능
    </li>
    </ul>

</li>
<li>

<ol>
<li>
<b>Render :</b> 컴포넌트를 호출해 어떻게 UI가 보여질지 계산한다.

컴포넌트를 실행한다.

</li>

</li>
</ol>
</li>

<ul>

</li>
</ul>
</li>
</ol>
</li>
<li>

- <b>리렌더링 : 컴포넌트 함수를 실행하고, UI를 계산한다 </b>
- 리렌더링 발생이라는 것은, 렌더 단계에서 발생
</li>
</ul>

### <b>Reconciliation 단계 : 컴포넌트 유지/재생성 판단 기준</b>

| 판단 기준 | React의 동작 |
| --- | --- |
| 같은 위치 + 같은 타입 + 같은 key | (동일성 유지)기존 요소와 상태 보존 |
| 같은 위치에서 타입 변경 | 해당 위치의 기존 요소 및 하위 트리를 교체 |
| <b>같은 타입이어도 key 변경</b> | <b><span color="blue">다른 컴포넌트로 취급해 상태 초기화</span></b> |

<p>
key : 위치가 바뀌어도 같은 컴포넌트임을 식별하는데에 관여 
</p>

### 마운트/언마운트 판단 기준

<ul>
<li>
key 변경 → 컴포넌트 동일성 상실 → state 초기화
</li>
<li>
컴포넌트 type 변경 → 기존 컴포넌트 교체 → 리마운트 → state 초기화
</li>
<li>
렌더 트리에서 제거 → 언마운트
</li>
<li>
트리 내 위치 변경 → 일반적으로 리마운트 되지만, 안정적인 key로 관리될 시 동일성/마운트 유지 
</li>
</ul>

<quote>
주의 할 점 : dom 요소(div → span) 변경은 상위 컴포넌트의 state 보존 
</quote>

### <b>Key가 변경되었을때</b>

```javascript
// 첫 번째 렌더링
<Counter key="A" />

// 다음 렌더링
<Counter key="B" />
```

- <b>React는 기존 Counter의 state를 보존할까, 아니면 초기화할까?</b>
  - <b>핵심 : 컴포넌트의 동일성, 상태 초기화</b>
  - React에서 state는 <b><span color="red">렌더 트리에서 컴포넌트 위치</span></b>와 동일성에 연결해서 관리한다.
  - 그런데, key가 바뀌면 이전 Counter와 새로운 Counter를 서로 다른 컴포넌트로 판단한다. → 동일하지 않음
  - 때문에 기존 Counter컴포넌트가 언마운트되고 새로운 Counter컴포넌트가 마운트되면 useState 상태값이 초기화가 된다.
- <b>key를 변경하지 않고 리렌더링된다면 state는?</b>
  <ul>
  <li>
  <b><span color="red">같은 위치에서</span></b> key가 변경되지 않고 컴포넌트가 리렌더링 될 경우 상태는 보존된다. 
  </li>
  </ul>

<h3>
트리 내 위치가 변경되었을때 
</h3>

```javascript
function App({ show }) {
  return (
    <div>
      {show && <Counter />}
      <Counter />
    </div>
  );
}
```

- <code>show</code>가 <code>true</code>에서 <code>false</code>로 바뀌면 두 번째 Counter의 state는 보존될까, 초기화될까?
  - <b>핵심 답변 : 보존된다. </b>첫 번째 Counter 컴포넌트가 사라진다고 해도 <b><span color="red">렌더 트리의 위치상 두 번째 Counter 컴포넌트는 동일한 위치</span></b>에 있습니다
- <code>show</code>가 true → false → true로 다시 바뀌면, 첫 번째 Counter가 이전에 가지고 있던 state는 복구될까, 아니면 초기화될까?
  - 핵심 답변 : 초기화된다. 렌더트리에서 새로운 컴포넌트가 생성되었기 때문에, 상태와 연결되어있던 <b><span color="red">이전 컴포넌트와 서로 다른 컴포넌트로 판단하여 이전 상태와의 연결이 끊길</span></b>것같습니다.
    - React는 컴포넌트의 state를 렌더 트리에서의 동일성에 연결해서 관리하니까 맞는말이라고 함.
    - <b>첫 번째 Counter의 생명주기</b>
      1. show = true \| 마운트 \| 초기값 state 생성
      2. show = false \| 언마운트 \| state 폐기
      3. show = true \| 새로 마운트 \| 초기값 state 생성

### 같은 부모 아래 리스트 항목이 순서만 변경되는 상황

```javascript
// 이전
<Item key="A" />
<Item key="B" />

// 이후
<Item key="B" />
<Item key="A" />
```

- 같은 부모 아래 같은 key값과 같은 요소의 타입일 경우 기존 컴포넌트의 동일성을 지켜, 리마운트 되지 않아서 상태가 초기화 되지 않고 상태를 보존할수있다.
  - 컴포넌트 동일성 유지 : 기존 local state 보존
  - 리마운트하지 않음 : state 초기화하지 않음
    <ul>
    <li>
    리렌더링은 발생할 수 있음 : state 보존과 별개 
    </li>
    </ul>

## 실제 사용 예시(사례)


```javascript
function App({ formKey }) {
  return <NameForm key={formKey} />;
}

function NameForm() {
  const [name, setName] = useState("");

  return (
    <input
      value={name}
      onChange={e => setName(e.target.value)}
    />
  );
}
```

- <b>사용자가 작성 중인 입력 폼에서 특정 조건에 따라 </b><b><code>key</code></b><b>를 변경하면 어떤 문제가 생길 수 있을까?</b>
  <ul>
  <li>
  사용자가 입력값에 “용채영”이라고 작성했는데, 부모컴포넌트의 formkey값이 변경될경우, key가 변경되어 동일성이 깨지고, 이전 컴포넌트가 언마운트되고 새 컴포넌트가 마운트되면서 상태가 초기화됩니다. 따라서 사용자가 작성해둔 입력값이 초기화되고, 입력창이 교체되면서 포커싱이 깨진다. 
  </li>
  </ul>

## 보조 개념 정리


- div 와 span은 dom 요소이다.
- 같은 타입일때 변경되는 다른 요소 → classname, style, text 등
- <b>렌더트리</b>
- <b>마운트 :</b> 렌더트리에 컴포넌트가 새로 등장함  : 초기값으로 생성됨
- <b>리렌더 : </b>기존 컴포넌트가 UI를 다시 계산함 : 동일성 유지 시 보존됨 == UI 재계산
- <b>언마운트 : </b>렌더트리에서 컴포넌트가 제거됨 : 해당 컴포넌트의 state 폐기
- <b>리마운트 : </b>기존 컴포넌트가 제거되고, 새 인스턴스로 다시 생성됨 : 초기값으로 생성됨.

- <b>UI 계산(render) ≠ dom에 UI 반영(commit) ≠ dom을 브라우저에 그리기(browser paint)</b>
