# 26-10-11 | 프로젝트 경험을 바탕으로 지원 문서와 설명 구조를 점검했다

## 1. Today I Learned

- 프로젝트 경험을 바탕으로 지원 문서와 설명 구조를 점검했다.
- 풀스택치고 포트폴리오가 프론트엔드에 치중되어있어서 데이터 전달 범위를 명시하기 위한 BE–FE 관심사 분리라는 주제로 페이지 하나 만들었습니다.

## 2. Insight

개인 프로젝트의 회고를 다시 살펴보며 API 설계 과정에서 고민했던 문제와 판단을 복기했다. 과거의 기록이 기술 경험을 설명 가능한 형태로 되살리는 데 도움이 됐다.

백엔드에서 DTO를 ReqDto와 ResDto로 분리하며 데이터의 저장과 전달 책임을 구분하는 이유를 이해했고, 프론트엔드에서도 비슷하게 ResProps와 ReqProps를 활용해 컴포넌트에 데이터를 전달하기 전에 필요한 정보를 조합하도록 했습니다. 이후 React를 깊이 공부하며 순수 함수와 사이드 이펙트를 분리해야 하는 이유를 이해했고, 이것이 현재 제 개발 컨벤션인 Pure UI와 Container 컴포넌트를 통해 데이터 조합과 UI 표현의 책임을 분리하는 방식으로 발전했다는 것을 깨달았습니다.

책임과 관심사를 분리해 유지보수하기 쉽고 이해하기 쉬운 코드를 작성하는 데 집중해 왔지만 개인적인 개발 습관으로만 남겨두어 과제테스트에서만 어필할 수 있었습니다. 그래서 이번에 마스터 포트폴리오 페이지에도 정리해 두기로 했습니다.
