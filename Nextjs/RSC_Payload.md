# RSC Payload

## 정의

- 정의
  - <b>서버 컴포넌트가 렌더링한 결과를 브라우저의 리액트에게 전달하기 위한 정보 </b>
- RSC payload에는 어떤 정보가 있나요?
  <ul>
  <li>
  서버 컴포넌트의 렌더링 결과와 클라이언트 컴포넌트를 연결하기 위한 정보 
  </li>
  </ul>
- rsc payload는 왜 필요한가?
  <ul>
  <li>
  <b>서버에서 실행한 결과</b>를 리액트가 이해할 수 있도록 전달합니다.
  </li>
  <li>
  어떻게 ? 직렬화된 데이터 형태로 
  </li>
  </ul>

## 특징

<b>클라이언트 컴포넌트도 서버에서 실행될수있다면, 서버에서도 실행되고 클라이언트에서도 실행되는것아닌가?</b>

> 초기 요청에는 클라이언트 컴포넌트 코드도 서버에서 렌더링에 참여되고, 브라우저에서도 JS를 실행한다.

<b>요청 흐름</b>

```ts
초기 요청

서버
Client Component도 렌더링에 참여
        ↓
초기 HTML 생성
        ↓
브라우저로 전달
        ↓
화면이 먼저 보임
        ↓
Client Component용 JS 다운로드/실행
        ↓
기존 DOM에 Hydration
```

- RSC payload에 들어가는 정보
  <ul>
  <li>
  서버 컴포넌트의 코드가 들어가지 않고, 
  </li>
  <li>
  <b>서버 컴포넌트의 렌더링 결과와 전체 리액트 트리구조를 이해하는데 필요한 정보가 들어간다.</b>
  </li>
  </ul>
- 서버 컴포넌트의 목적이 다른 두 산출물
  - html
    - 초기 페이지를 바로 보여주기 위한 결과
  - RSC paylosd
    - 리액트가 이해할 수 있는 서버 컴포넌트의 결과
    - 리액트가 서버에서 렌더링한 결과와 서버/클라이언트 컴포넌트를 이해하기 위한 정보
  - <b>하나의 리액트 트리를 서버에서 렌더링하지만, 브라우저에게 필요한 결과물이 목적에 따라 구분된다.</b>
- RSC payload
  - <b>리액트가 리액트 트리를 이해하기 위해 필요하다.</b>
  - <b>즉, 서버에서 서버컴포넌트를 렌더링한 결과를 브라우저의 리액트에게 전달하기 위한 정보</b>
- HTML 없이 RSC Payload와 Client Component JS만 있다면, 이론적으로 브라우저가 그 정보를 이용해서 화면을 만들어낼 수는 없을까?
  - CSR과 비슷하게, 클라이언트 컴포넌트로 브라우저에서 html을 새롭게 만드는 것 아닐까?
  - RSC payload에는 이미 서버 컴포넌트의 결과가 있으니까 CSR 처럼 ui를 처음부터 새롭게 만드는것과 다르다.

```ts
                 서버에서 React 트리 렌더링
                          │
             ┌────────────┴────────────┐
             │                         │
        초기 HTML                  RSC Payload
             │                         │
      브라우저가 바로             React가 이후에도
       화면을 표시              컴포넌트 트리를 이해
```

<callout icon="💡" color="yellow_bg">
<b>주의 : 컴포넌트 실행 → RSC 완성 → html 완성!으로 외우면 안됨</b>
</callout>

<callout icon="💡" color="brown_bg">
핵심

<ul>
<li>
서버 컴포넌트의 원본 react 코드 : 브라우저로 안감
</li>
<li>
서버에서 렌더링한 결과 : RSC payload에 포함됨
</li>
<li>
초기 페이지를 바로 보여주기 위한 결과 : html로 만들어져 브라우저로 감 
</li>
</ul>
</callout>

## 보조 개념 정리

<ul>
<li>
서버 컴포넌트 

- 브라우저에서는 모르는 코드
- 서버에서만 실행
</li>
<li>
클라이언트 컴포넌트 

- 브라우저로 기존 dom에 하이드레이션 하는 코드
- 초기 서버 컴포넌트와 함께 렌더링에 참여

> <b>서버와 브라우저가 각각 알고 있는 것.</b>

|  | 서버 | 브라우저 |
| --- | --- | --- |
| 서버 컴포넌트 코드 | O | <b>X</b> |
| 클라이언트 컴포넌트 코드 | O | <b><span color="red">O</span></b> |
| 서버가 만든 초기 HTML | 생성 | <b><span color="red">전달받음</span></b> |
|  |  |  |
</li>
<li>
서버에서 브라우저로 전달하는 것

- rsc payload
- html
- 클라이언트 컴포넌트
</li>
<li>
컴포넌트 

- 모든 서버 파일이 리액트 컴포넌트 인것이아니라, 렌더링 html 코드를 반환하면 컴포넌트이다.
- 이 들 중 컴포넌트는 서버 컴포넌트과 클라이언트 컴포넌트로 나뉘는것
- <b>http 요청을 처리하는 엔드포인트 코드와 헷갈리지 말기</b>
  ```ts
  서버에서 실행되는 코드
  │
  ├─ React UI 계층
  │   ├─ Server Component
  │   └─ Client Component
  │
  └─ 서버 로직
      ├─ Route Handler
      ├─ BFF/API 로직
      └─ 기타 서버 코드
  ```
</li>
<li>
렌더링

- <b>= UI계산</b>
- 컴포넌트를 실행해서 어떤UI구조인지 계산하는 과정
</li>
<li>
리액트 트리

- <b>= 리액트 구조</b>

```ts
function Page() {
  return (
    <main>
      <h1>안녕 채영</h1>
      <p>오늘 일정이야</p>
    </main>
  );
}
```

```ts
Page
 └─ main
     ├─ h1
     │   └─ "안녕 채영"
     └─ p
         └─ "오늘 일정이야"
```
</li>
<li>
<b>직렬화</b>

- 네트워크로 전달할 수 잇는 데이터 형태
</li>
</ul>
