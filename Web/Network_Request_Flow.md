# 웹 네트워크 요청 흐름

## 1. 배경과 맥락

> <span color="gray">어떤 이유 때문에 필요 했는가? </span>

- 프론트엔드 개발을 하다 보면 CSR, SSR 같은 렌더링 전략에 집중하게 되는데, 그 전에 먼저 이해해야 할 것이 있다.
  - <b>브라우저, 네트워크, CDN, 서버가 각각 어떤 역할을 하는가</b>

## 2. 기술 키워드

> <span color="gray">키워드 위주로 적고 말로 설명하는 연습을 합시다. </span>

- <b>프론트 서버란? : React / Next.js 코드가 실행되거나, 그 결과물(HTML)을 서빙하는 주체</b>
  1. <b>실행 중인 프론트 서버</b>
     - Node.js / Edge Runtime
     - Next.js 서버 , Vercel, Lambda 등
       - <b>코드를 실행해서 HTML을 만들어냄 : 즉석 빌드</b>
  2. <b>결과물만 있는 프론트 서버(CDN)</b>
     - S3 + CloudFront
     - Nginx 정적 서버
       - 이미 만들어진 HTML 파일을 전달만 함
- 네트워크란?
  - TCP/IP, TLS, 라우팅, 인터넷 구간
  - CDN 엣지 서버
  - 오리진 서버
  - Network / Server-side 영역

  ```txt
  Browser Network Stack
            ↓  ← 이 경계부터
         Internet
            ↓
          CDN
            ↓
       Origin Server
  ```
- <b>빌드 : 파일을 미리 만들다.</b>
  - 언제: 개발자가 명령을 실행할 때 (<code>next build</code>)
  - 무엇을:
    - TypeScript → JavaScript
    - JSX → JS
    - (SSG일 경우) <b>HTML 파일 생성</b>
  - 결과물: 파일 - HTML, CSS,JS파일 . . .
  - <b>실행할 준비물을 만드는 과정</b>

  - <b>서버 : 요청이 들어오면 판단하고 계산하는 주체</b>
  - 언제: 사용자가 <b>요청</b>할 때마다
  - 무엇을:
    - 코드 실행
    - 데이터 조회
    - 조건 분기
    - SSR/ISR 일경우 ; HTML 생성
  - 결과물: 응답(Response)
  - 서버는 요청을 받으면 <b>정적 리소스 데이터</b>를 반환해준다.(JS번들도 정적 리소스이다.)

## 3. 고민했던 내용과 인사이트

> <b>네트워크와 서버의 차이는 무엇인가? </b>

- <b>서버 :</b> 요청이 들어오면 계산하고 응답을 돌려줌
  - 처리함 (처리하는 뇌)
- <b>네트워크 :</b> 요청과 응답 사이에서 더 빠르게 수행할수있음.
  - 처리한 정적 리소스를 처리하는 통로 (통로)

> <b>동적과 정적 차이</b>

- <b>동적 :</b> 요청 시점에 내용이 바뀔수있음 .
  - DB데이터에 따라 실시간으로 데이터가 달라짐.
- <b>정적 :</b> 빌드 - 한번 생성되면 변하지 않는다. (스냅샷)

> <b>정적 배포란 무엇인가?</b>

- <b><span color="blue">소스 코드 → 빌드</span></b> → 정적 산출물(HTML, JS, CSS) → CDN 업로드 → 사용자 요청

- 빌드가 안되면 → 산출물이 없고 → CDN에 올릴 파일이 없기 때문에 배포 불가능

> <b>동적 서버란 무엇인가?</b>

- <b><span color="blue">소스 코드 → 빌드</span></b> → 서버 실행 환경 배포 → 서버가 HTML 생성 → CDN 캐싱(optional)
  <ul>
  <li>
  이때 CDN은 , CDN은 정적 파일만 캐싱하는 게 아니라

  - (HTML, CSS, JS 번들 뿐만이 아니라 !) <b>서버 응답 자체를 캐싱하는 레이어일 수도 있음</b>
  </li>
  </ul>
